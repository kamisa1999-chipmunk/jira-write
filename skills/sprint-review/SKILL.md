# Sprint review

## Назначение

Снимок активного спринта из Jira → файлы в `reports/` → краткий разбор для тимлида. Уточнения — по **тому же** отчёту, без повторного запроса в Jira.

Токен не читать и не показывать. Цифры — только из JSON. Ссылки: `[CAT2-1234](https://jira01.goldapple.ru/browse/CAT2-1234)`.

## Когда ходить в Jira

| Ситуация | Действие |
|----------|----------|
| Есть отчёт по этому спринту **< 8 ч** | Читать JSON, скрипт не запускать |
| Уточнение («а у Димы?», «что в To Test?») | Тот же отчёт |
| Отчёт старше 8 ч или «обнови / пересобери / сходи в jira» | Новый запуск CLI → **новый** файл |

## Команда

```bash
python3 scripts/cli/get_sprint_snapshot.py
# опционально:
python3 scripts/cli/get_sprint_snapshot.py --project CAT2 --format both
```

Перед первым запуском: `pip3 install -r scripts/requirements.txt`. Скрипт может работать 10–30 сек.

Имя файла: `{YYYY-MM-DD}_{HH-MM}__{PROJECT}__sprint-{id}__{start}__{end}.json` (+ `.md`). Старые отчёты не перезаписывать.

## Что показать в ответе

1. **Цели** — `sprint.goal`
2. Название спринта и период
3. **Прогресс** — `summary.by_category` (не только сырые статусы)
4. **Риски** — задачи с непустым `risks` (`over_estimate`, `stuck_in_work`, `long_in_status`, `returned_after_testing`)
5. **Неназначенные** / **без оценки** — `summary.unassigned`, `summary.without_estimate`
6. Очередь теста (`testing_queue`), при необходимости нагрузка по `by_assignee`

Не вываливать весь список задач без запроса. Уточнения — фильтр по `issues` того же JSON; в ответе указать время отчёта.

Оценки в **часах** (`estimate_hours`, `spent_hours`). Testing-задачи помечены `is_testing_task: true` — считать отдельно от dev при планировании.

Статусам частично доверяем: факты из JSON отдельно от интерпретации. Carry-over — только как осторожная гипотеза, без гарантий.

## Перед планированием

Тот же снимок + акцент: цели, категории, риски, неназначенные/без оценки, вероятный carry-over (не Done / To Prod / Canceled), вопросы «что режем / где перегруз».

## Чего не делать

- Не просить токен и не коммитить `.env`
- Не перезапускать скрипт при уточнениях, если отчёт свежий
- Не додумывать цифры
- Не удалять и не перезаписывать старые отчёты
