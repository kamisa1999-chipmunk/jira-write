# Sprint management

## Назначение

По датам пользователя:

1. создать новый спринт в Jira;
2. настроить автоматический запуск и завершение;
3. настроить перенос незавершённых задач в следующий спринт;
4. сформировать цели спринта на основании файлов по фичам;
5. создать дочернюю страницу спринта в Confluence;
6. сохранить ссылку на страницу в цели спринта Jira.

Токены Jira и Confluence не читать и не показывать. Без preview и подтверждения ничего не создавать.

## Триггеры

- «Создай спринт CAT2 с 27 июля по 7 августа»
- «Подготовь следующий спринт»
- «Создай следующий спринт и страницу в Confluence»
- «Покажи preview нового спринта»
- «Проверь настройки нового спринта»

## Источники (только эти)

| Что | Где |
|-----|-----|
| Jira CLI / сервисы | `scripts/` |
| Конфиг спринта | `scripts/config/sprint_management.yaml` |
| План фич | опционально: `features/` в текущем workspace; иначе цели только из текста пользователя |
| Родитель Confluence | pageId `823380099` |
| Секреты | `scripts/.env` (`JIRA_*` и отдельно `CONFLUENCE_*`) |

Не исследовать весь репозиторий. Не ходить в Automation, если `autoStartStop` / `incompleteIssuesDestinationId` доступны через Agile API.

## CLI

```bash
# preview (ничего не пишет)
python3 scripts/cli/manage_sprint.py \
  --start 27.07.26 --end 07.08.26 \
  --goal "…" --goal "…"

# после явного «да / создай / применяй»
python3 scripts/cli/manage_sprint.py \
  --start 27.07.26 --end 07.08.26 \
  --goal "…" --goal "…" --apply

# проверить существующий
python3 scripts/cli/manage_sprint.py --verify 5873

# продолжить после частичного сбоя
python3 scripts/cli/manage_sprint.py --preview-file preview.json --resume state.json --apply
```

Перед первым запуском: `pip3 install -r scripts/requirements.txt`.

## Workflow

### 1. Подготовка

1. Определи даты из запроса (`DD.MM.YY` / «с 27 июля по 7 августа»). Если дат нет («следующий спринт») — возьми конец предыдущего датированного CAT2 и предложи стандартные +2 недели, уточни у пользователя.
2. Если в workspace есть `features/` — прочитай файлы за период и набросай цели. Если нет — цели только из текста пользователя, ничего не выдумывать.
3. Запусти CLI **без** `--apply` → preview.
4. Покажи preview пользователю. Без подтверждения **не** вызывать `--apply`.

Preview должен содержать:

* название;
* даты;
* доску;
* родительскую страницу Confluence;
* проект целей;
* правило переноса незавершённых задач;
* какие настройки будут применены автоматически.

### 2. Цели

Прочитай только файлы, относящиеся к периоду нового спринта. Определи:

* какие фичи должны завершить разработку;
* какие должны перейти в тестирование;
* какие должны быть подготовлены к релизу или выпущены;
* какие аналитические работы должны завершиться;
* какие технические работы запланированы;
* какие обязательства и контрольные точки попадают в даты спринта.

Сформируй короткие, конкретные и проверяемые цели.

Не включай весь список задач и не придумывай обязательства, которых нет в файлах.

Пример:

```markdown
1. Завершить тестирование рекламных позиций и подготовить их к релизу.
2. Завершить разработку нового отображения промокодов.
3. Подготовить к разработке фильтр по акциям.
4. Выполнить согласованный объём технического долга.
```

Перед созданием спринта и страницы обязательно покажи цели пользователю и разреши:

* изменить формулировку;
* добавить цель;
* удалить цель;
* подтвердить список.

### 3. Apply (после «да»)

Порядок (делает CLI):

1. Создать спринт.
2. Получить ID и ссылку на дашборд.
3. Создать страницу Confluence.
4. Получить URL страницы.
5. Записать цели и ссылку в Jira goal.
6. Настроить `autoStartStop`.
7. Настроить `incompleteIssuesDestinationId`.
8. Повторно прочитать и проверить.

Если шаг упал: не повторять успешные; показать создано / осталось; продолжить через `--resume`.

### 4. Итог

```markdown
Спринт создан: 3. CAT2 27.07.26 - 07.08.26
Jira: ...
Confluence: ...

Настройки:
- автоматический запуск: настроен;
- автоматическое завершение: настроено;
- незавершённые задачи: в следующий спринт.

Цели:
1. ...
2. ...
3. ...
```

## Именование

```text
{номер}. CAT2 DD.MM.YY - DD.MM.YY
```

Номер = max по дочерним страницам Confluence родителя `823380099` + 1.  
Дубликаты по датам/названию (Jira или Confluence) → preview `ready: no`, не создавать.

## Механизмы Jira (важно)

| Настройка | Механизм | Поле API |
|-----------|----------|----------|
| Автозапуск / автозавершение | Нативный Agile | `autoStartStop: true` |
| Перенос незавершённых | Нативный Agile | `incompleteIssuesDestinationId` (`−1` = backlog, id = следующий спринт) |

Не имитировать успех. Если API отклонил поле — явно написать, что требует ручной настройки в UI доски.

### Правило переноса

Перед настройкой посмотри предыдущий датированный спринт:

* если незавершённые шли в следующий спринт — сохранить поведение;
* если шли в backlog (`−1`) / unset — при создании нового выставить destination предыдущего на id нового;
* если следующего спринта ещё нет — у нового destination = backlog и пометка «настроить после создания следующего».

Не переносить задачи вручную. Не менять состав предыдущего спринта и backlog.

## Confluence

Родитель: `https://confluence.goldapple.ru/pages/viewpage.action?pageId=823380099`

Перед созданием CLI / агент опирается на формат существующих дочерних страниц: toc-макрос, `Дашборд`, `Цели`, `Результаты`. Название страницы = название спринта.

В goal Jira после создания:

```text
1. …
2. …

Подробнее: https://confluence.../...
```

Если goal длинный — короткие цели + обязательная ссылка; полная формулировка на странице.

## Ограничения

* Не создавать спринт без preview и подтверждения.
* Не придумывать цели.
* Не добавлять задачи в новый спринт.
* Не переносить задачи вручную при создании.
* Не менять содержимое предыдущего спринта.
* Не создавать дубликаты страниц и спринтов.
* Не выводить токены Jira и Confluence.
* Использовать отдельные конфигурации для Jira и Confluence.
* Не создавать unit-тесты.
* Не рефакторить несвязанные части проекта.
