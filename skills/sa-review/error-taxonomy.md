# Категории замечаний SA-review

Категории используются для группировки замечаний в отчёте ревьюеру.

Английский идентификатор — техническое стабильное имя категории.
Русское название — человекочитаемое описание.

В Jira-комментариях технические идентификаторы категорий не показываются.

## Категории

Идентификаторы не менять и не изобретать синонимы без нужды.

| Идентификатор | Русское название | Что означает |
| --- | --- | --- |
| `scenario-coverage` | Полнота сценариев | Не описан один или несколько значимых сценариев поведения |
| `entry-point-coverage` | Покрытие точек входа | Не учтены все точки входа или экраны, затронутые изменением |
| `platform-differences` | Различия платформ | Не зафиксированы различия Web/iOS/Android или других платформ |
| `ecosystem-impact` | Учет связанных компонентов | Изменение рассмотрено локально, без связанных методов, систем, UI или контрактов |
| `contract-versioning` | Версии контрактов | Неясно, как изменение влияет на разные версии контракта |
| `contract-level-mixing` | Смешение уровней контрактов | В одной спецификации смешаны разные уровни, например SDK и BFF/HTTP |
| `null-empty-behavior` | Поведение для пустых значений | Не описано поведение при отсутствии поля, `null` или пустом значении |
| `edge-cases` | Граничные и альтернативные сценарии | Не описаны значимые альтернативные, ошибочные или граничные состояния |
| `decision-traceability` | Фиксация решений | Принятое решение не отражено в актуальной документации |
| `decision-rationale` | Обоснование решения | Решение зафиксировано, но отсутствует необходимая причина |
| `review-comments-processing` | Обработка замечаний ревью | Предыдущее замечание не отражено изменением или согласованным решением |
| `naming-consistency` | Единообразие терминов | Один объект называется по-разному в связанных артефактах |
| `docs-consistency` | Непротиворечивость документации | Связанные документы описывают разное поведение |
| `docs-relevance` | Актуальность документации | Документация не соответствует текущему решению или реализации |
| `testability` | Проверяемость | По описанию нельзя однозначно проверить ожидаемый результат |
| `jira-task-quality` | Качество задач Jira | Задача не содержит информации, необходимой исполнителю |
| `implementation-feasibility` | Выполнимость | Описанное решение нельзя реализовать однозначно или оно конфликтует с известными ограничениями |

Ориентир по разделам чек-листа (не взаимно однозначно):

| Раздел чек-листа | Типичные категории |
|------------------|-------------------|
| 1. Схема | Учет связанных компонентов (`ecosystem-impact`) |
| 2. Сценарии и точки входа | Полнота сценариев, покрытие точек входа, различия платформ |
| 3. Спецификации и шаблоны | Непротиворечивость и актуальность документации, экосистема, версии и уровни контрактов |
| 4. Однозначность / имена | Единообразие терминов |
| 4. Полнота | Поведение для пустых значений, граничные сценарии |
| 4. Решения | Фиксация и обоснование решений |
| 4. Непротиворечивость | Непротиворечивость документации |
| 4. Проверяемость | Проверяемость |
| 4. Актуальность | Актуальность документации |
| 4. Выполнимость | Выполнимость |
| 5. Задачи в Jira | Качество задач Jira |
| 6. Передача / прошлые замечания | Обработка замечаний ревью |

Одна проблема — одна основная категория. Дополнительную не плодить.

Во внешнем ревью писать русское название, не голый идентификатор.

## Повтор внутри одной задачи

| Идентификатор | По-русски | Что означает |
| --- | --- | --- |
| `unresolved_previous_review` | Повтор предыдущего замечания | Замечание предыдущей итерации ревью этой же задачи не закрыто |
| `unresolved_previous_comment` | Необработанное замечание прошлого ревью | Конкретное замечание предыдущего ревью осталось необработанным |

Не смешивать незакрытое замечание прошлого ревью с новым «есть замечание» той же сути.
